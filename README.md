# To-Do App

A per-user to-do list: sign up with a Gmail address, verify it with a code, then add, edit,
complete and delete your own tasks. Users can never see or change each other's tasks.

- **Frontend:** React + TypeScript + Vite, Tailwind CSS
- **Backend:** AWS Amplify Gen 2 — Cognito (accounts), AppSync GraphQL API, DynamoDB (tasks),
  one small Lambda (signup check) — all serverless and pay-per-use, in **ap-south-1 (Mumbai)**
- **Hosting:** Amplify Hosting, auto-deployed from the `main` branch on GitHub
- **Quality:** Vitest + React Testing Library, ESLint + Prettier, GitHub Actions CI

## How it works

```
Browser (React) ──HTTPS──▶ Amplify Hosting (static site + security headers)
   ├──▶ Cognito: sign-up / login / email codes / password reset
   │       └── pre-sign-up Lambda: rejects non-@gmail.com and "+" addresses (server side)
   └──▶ AppSync API ──▶ DynamoDB "Task" table
           ├── list / get / delete: Amplify owner-only rules
           └── addTask / editTask: custom resolvers that validate input and set/check the owner
```

Key security decisions:

- **Gmail-only signup is enforced on the server** by a Cognito pre-sign-up trigger
  (`amplify/auth/pre-sign-up/`), not only in the form. Addresses containing `+` are rejected.
- **Password policy** (8+ characters, upper, lower, number, symbol) is set on the Cognito user
  pool itself (`amplify/backend.ts`).
- **Owner-only data:** every task stores its owner from the caller's verified Cognito identity.
  Amplify's generated create/update mutations are disabled; `addTask`/`editTask`
  (`amplify/data/*.js`) validate input on the server, and `editTask` only writes if the stored
  owner matches the caller (an atomic DynamoDB condition).
- **Same validation rules in browser and server:** `shared/validation.ts` (signup) is used by
  both; task limits are duplicated in the resolvers and kept in sync by tests.

## Local setup

Prerequisites: Node.js 22+, npm, the AWS CLI with an IAM Identity Center profile
(`aws configure sso`, profile name `todo-dev`, region `ap-south-1`) that has the
`AmplifyBackendDeployFullAccess` policy.

```bash
npm ci                                          # install exact dependency versions
aws sso login --profile todo-dev                # when your AWS login has expired
npx ampx sandbox --once --profile todo-dev      # deploy YOUR private dev backend
npm run dev                                     # http://localhost:5173
```

The sandbox is a separate copy of the backend for development: its users and tasks are not
production data. `npx ampx sandbox` (without `--once`) keeps watching `amplify/` and redeploys
on every change. Delete the sandbox with `npx ampx sandbox delete --profile todo-dev`.

`amplify_outputs.json` (backend addresses and IDs, generated by the sandbox or by Amplify
Hosting) and `.env.local` are git-ignored. **No secrets are stored in the repository.**

### Authorization test (sandbox only)

`integration/authz.test.ts` signs in as two real **sandbox** users and proves user B cannot
list, read, edit, complete, delete or forge ownership of user A's task. It refuses to run
unless `amplify_outputs.json` comes from the sandbox, and it deletes the tasks it creates.

1. Sign up two accounts in the sandbox app (tip: Gmail ignores dots, so `ab@gmail.com` and
   `a.b@gmail.com` reach the same inbox but are different accounts here).
2. Copy `.env.example` to `.env.local` and fill in `AUTHZ_USER_A_*` / `AUTHZ_USER_B_*`.
   Use sandbox-only passwords.
3. `npm run test:authz`

It is not part of CI because it needs AWS credentials and real users.

## Deployment (Amplify Hosting)

Every push to `main` triggers an Amplify Hosting build (`amplify.yml`):

1. `npm ci`, then type-check and unit tests — **a failure stops the deploy**
2. `npx ampx pipeline-deploy` deploys the `main` branch's own backend
   (separate users and tasks from your sandbox)
3. `npm run build`, then the site is published over HTTPS

One-time setup (already done for this project): in the Amplify console, create an app from
GitHub → `todo-app` → `main`, let Amplify create its service role, and add the single-page-app
rewrite rule (source `</^[^.]+$|\.(?!(css|gif|ico|jpg|js|png|txt|svg|woff|woff2|ttf|map|json|webp)$)([^.]+$)/>`,
target `/index.html`, type `200 (Rewrite)`) so that refreshing `/tasks` works.

**Production-only protections** (`amplify/backend.ts`, when `AWS_BRANCH` is `main`):
DynamoDB point-in-time recovery (restore to any second in the last 35 days) and deletion
protection on the task table and the user pool.

## Costs

Everything is serverless and billed per use — nothing runs (or bills) while idle. Prices below
are approximate for ap-south-1; check the AWS pricing pages for current numbers.

| Service                 | Free allowance (approx.)                             | After that (approx.)                      |
| ----------------------- | ---------------------------------------------------- | ----------------------------------------- |
| Cognito user pool       | 10,000 monthly active users                          | per active user                           |
| Cognito emails          | Built-in sender, ~50 emails/day                      | Use Amazon SES for more                   |
| AppSync                 | 250,000 requests/month (first 12 months)             | ~$4 per million requests                  |
| DynamoDB (on-demand)    | 25 GB storage                                        | ~$1.25 per million writes                 |
| DynamoDB backups (PITR) | —                                                    | ~$0.20 per GB-month (tiny for this app)   |
| Lambda (signup check)   | 1 million runs/month                                 | fractions of a cent                       |
| Amplify Hosting         | 1,000 build minutes, 5 GB storage, 15 GB transfer/mo | ~$0.01 per build minute, ~$0.15/GB served |
| CloudWatch Logs         | 5 GB/month                                           | per GB                                    |

Expected cost for personal use: **$0 – a few cents per month**. Each push to `main` uses a few
build minutes. A **$1/month AWS Budget alert** is set up on the account (Billing → Budgets).

To stop all costs: delete the Amplify Hosting app (removes the production backend — note the
deletion protection above must be turned off first), and run
`npx ampx sandbox delete --profile todo-dev`.

## Known limitations

- Gmail ignores dots, so `john.doe@gmail.com` and `johndoe@gmail.com` are the same inbox but
  separate accounts here (each must still be verified via that inbox).
- Cognito's built-in email sender is limited (~50 emails/day); production use beyond that
  needs Amazon SES.
- Login tokens are stored in the browser's localStorage (Amplify default); a cross-site
  scripting bug could expose them. The strict Content-Security-Policy reduces that risk.
- `npm audit` reports issues in AWS's Amplify **developer tooling** (code generators and the
  deploy CLI). None are in the code shipped to browsers (`npm audit --omit=dev` is clean).
- ESLint is pinned to v9 because `eslint-plugin-jsx-a11y` does not support v10 yet, and
  TypeScript to 6.0 because `typescript-eslint` does not support 7 yet.
- The production JavaScript bundle is ~545 KB (≈165 KB gzipped), mostly the Amplify library;
  Vite warns about its size. It could be split into smaller chunks later.
- No offline support, sharing, reminders or multi-factor authentication.
- The app has automated tests but is **not guaranteed bug-free** — see the pre-launch checklist.
